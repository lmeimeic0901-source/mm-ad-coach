# 探店、探厂与现场溯源广告

用户明确要探店、探厂、工厂溯源、检测中心、门店挑战、现场选购或依据拍摄素材完成这类广告时读取。普通单品、普通好物分享和普通科普不读取本文件。

## 一、两类任务不同

### 探厂／检测中心／溯源

核心任务：替消费者查清一个普通广告无法确认、必须到现场才能验证的购买问题。

推荐结构：

`消费者怀疑 → 初始猜测 → 现场验证 → 追原因 → 发现限制 → 修正判断 → 适合／不适合／尚未证明`

禁止按“门口—原料—生产线—实验室—负责人采访—卖点总结”写成参观流水账。厂房大、机器多、员工忙只能是环境画面，不能单独证明产品更好。

### 探店／现场选购

核心任务：在明确限制下替消费者完成一次选择或淘汰。

推荐结构：

`购买任务与限制 → 候选出现 → 现场体验／同维度比较 → 淘汰或保留 → 排名变化 → 最终购物篮／适合人群`

禁止拿起一个产品就从头念卖点，也不把完整门店导览误当成购买理由。

## 二、切入点生成

先从 Brief、用户真实经验和现有材料暂定：

1. 消费者买前最怕判断错什么；
2. 哪个差异只有到店／进厂才看得到；
3. 现场可以完成什么动作、抽样、比较或追问；
4. 什么结果算通过、什么结果会改变推荐；
5. 现场无法证明的部分是什么。

没有学员补充时，Agent 先给 3 个具体方案并推荐一个，不先要求学员回答抽象的目标人群和消费痛点。

## 三、拍前与拍后事实分层

拍前统一使用：

- 【已确认】：用户经历、Brief 事实或已取得证据；
- 【预计拍摄】：可以安排的镜头、路线、动作和提问；
- 【现场待核验】：必须到现场才知道的结果；
- 【结果分支】：不同结果出现时怎样继续拍、怎样修改判断。

拍前可以写完整叙事和执行脚本，但不能写“结果证明、老板承认、现场果然、随机抽到”等尚未发生的事实。

## 四、三阶段交付

### 1. 创意大纲

给 3 个真正不同的候选，每个包含：

- 观众为什么看；
- 开头事件；
- 3 个现场动作或证据；
- 品牌卖点怎样自然进入；
- 预期风险和拍摄条件。

明确推荐一个，并说明为什么最适合现有 Brief 和博主人设。

三套探厂候选必须分别绑定不同的消费者购买疑问、第一项现场动作和主要证据链。耐久、轮组、折叠结构、装配过程等材料要被分配到不同验证任务，不能把同一套“找松动／看磨损／问工程师”换成进度条、找茬卡或挑战赛后重复交付。

### 2. 拍前执行稿

交付：完整主线、镜头任务、现场提问、证据清单、品牌必拍、结果分支和补拍清单。不要停在笼统大纲，也不要预写现场结论。

### 3. 拍后成片稿

用户提供视频、逐字稿或完整现场记录时：

1. 保留一份完整原始逐字稿，不因重组而丢失；
2. 按真实时间整理事件、人物原话和可见结果；
3. 区分现场证据、品牌说法、本人判断和仍未证明；
4. 重排成“问题—动作—证据—判断变化”的成片结构；
5. 补写必要旁白、花字和完整可剪净稿。

平台支持创建文件且材料较长时，至少生成一个可单独打开的交付物：

- Word／Markdown：完整逐字稿、原话与最终净稿；
- Excel：时间码、镜头、原话、内容作用、事实来源、保留／删除、补拍；
- 对话内另给一张简洁结构卡，帮助快速看懂，不用大表格淹没正文。

平台不支持文件时，在对话中交付同样字段，不谎称已生成附件。

## 五、持续观看与信息密度

第一项现场结果不能直接结束整条内容。它应自然产生下一次追问、比较或验证。每段至少新增：问题、动作、证据、限制或判断变化中的一项。

现场惊险、突袭、冲突和大动作只有在安全、可执行且与购买问题直接相关时使用；不为高光设计危险行为，不承诺品牌允许进入未确认区域。

## 六、完成检查

- 内容有一个购买问题，而不是“带大家参观”；
- 所有现场环节都回答这个问题；
- 至少有一处真实判断变化或适用边界；
- 没有把品牌安排的流程伪装成随机发现；
- 没有提前编现场结果、人物原话、价格、库存或服务；
- 结尾说明适合谁、不适合谁或还有什么没有证明，而不是无条件夸品牌。
