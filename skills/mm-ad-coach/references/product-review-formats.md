# 单测与横测广告

用户明确要测评、评测、对比、单测、横测、多款 PK、同品类怎么选时读取。测评属于广告创作；用户拿来一篇独立完整成稿要求逐句审核时，仍转交 MM-广告改稿。

## 一、先分单测和横测

### 单测

观众对这一款感兴趣，但还在判断它值不值得买、适不适合自己。

核心任务：围绕一个明确购买疑问，对单个产品进行可复现的体验或验证，最后给有边界的购买结论。

推荐结构：

`为什么测这一款 → 先公布判断问题／测试方法 → 实际动作与结果 → 优势成立在哪里 → 限制或不适合谁 → 有条件结论`

### 横测

观众已经决定购买这个品类，但正在多个产品之间纠结。

核心任务：让候选产品在相同维度、相近条件和可比较来源下竞争，最后给不同需求的选择结论。

推荐结构：

`为什么会纠结／为什么测这几款 → 先公布比较规则 → 同维度逐项比较 → 优劣势与代价 → 排名或选择变化 → 分人群推荐`

## 二、测评前先建比较账本

内部记录：

| 项目 | 内容 |
| --- | --- |
| 购买问题 | 这次测试到底要帮观众决定什么 |
| 对象 | 单个产品或明确候选产品 |
| 维度 | 2—4 个直接影响选择的同类维度 |
| 条件 | 测试环境、步骤、样本和限制 |
| 来源 | 本人实测、品牌资料、公开参数、报告或待核对 |
| 结果 | 已确认结果／现场待核验／没有数据 |
| 结论边界 | 哪类人适合、哪类人不适合、还有什么没证明 |

资料量更多不等于产品更好。目标品牌的资料明显比竞品完整时，不能把“没有竞品数据”当成目标品牌胜出。

## 三、单测硬门

- 测试维度来自真实购买问题，不为展示功能随意设计；
- 测试方法让观众看得懂，必要时说明它只能代表本次条件；
- 测试动作、观察结果和解释分开，不把一个画面升级成专业结论；
- 没有实际测试时只交付拍摄方案和结果分支，不使用“实测发现”；
- 既说优势，也交代会影响购买的限制；
- 噱头、热点和痛点只负责引入，正文必须回到测试和购买判断。

## 四、横测硬门

- 开头快速交代纠结原因和为什么比较，不长篇普及品类常识；
- 所有候选尽量使用同一维度、相近条件和同类来源；
- 不只挑目标产品占优的维度；
- 优势必须同时说明代价或适用条件；
- 品牌对比表、报告、公开参数和本人实测保持来源词，不能混成一次个人横测；
- 结论允许“不同人选不同款”，不为广告强行制造无条件第一名；
- 缺少关键可比数据时，收窄成选购标准或拍摄计划，不伪造结果。

## 五、测评高光

先确定购买疑问，再从可见动作、同维度反差、结果悬念、淘汰过程或真实限制中找高光。盲测、暴力测试、限时挑战、价格冲击都不是默认模板。

如果一个测试无论出现什么结果都不会改变推荐，它只是产品演示，不是有效测评。

## 六、交付方式

### 只有资料，尚未拍摄

交付：当前判断、2—3 个测评方向、推荐方向、测试维度、拍摄动作、结果分支和一个具体教练选择。

### 已有真实测试记录

交付：测试口径、确认结果、优势与限制、适合人群、完整可拍稿和一个具体教练选择。

### 多产品数据确实适合表格

可以先用简洁对比表说明来源、维度、结果和边界，再写口播。不要把完整脚本默认塞进大表格。
